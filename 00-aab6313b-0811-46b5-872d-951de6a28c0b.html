Présentation du projet

Ce que vous allez faire

Pendant cinq séances, vous allez construire seul(e) un site web complet consacré au jeu vidéo Blue Prince. Il s'agira d'une grande page d'accueil qui présente le jeu et d'une page de mentions légales.

Ce projet a un objectif simple : mettre en œuvre tout ce que vous avez vu en HTML, en CSS et en JavaScript et approfondir par la pratique trois notions abordées rapidement en cours d'intégration : Flexbox, Grid et les media queries.

Vous ne partez pas de rien. Vous recevez :

  • des captures du site final, en version ordinateur et en version mobile : c'est le résultat à atteindre dans l'idéal ;
  • tous les textes, au format .txt ;
  • toutes les images, déjà aux bons formats.

Vous n'avez donc ni contenu à rédiger, ni image à chercher : tout votre temps est consacré au code. Vous n'avez pas besoin de connaître Blue Prince, ni même d'aimer les jeux vidéo : le jeu sert seulement de support. Ce qui compte, c'est la façon dont vous construisez le site.

Chaque partie commence par une fiche qui détaille les étapes à suivre. Suivez-les dans l'ordre : chaque partie s'appuie sur la précédente.

Comment vous allez travailler

En autonomie. Les parties ne sont pas des cours : vous avancez à votre rythme avec la fiche de la partie. L'enseignant est là pour répondre à vos questions et vous débloquer. N'hésitez pas à l'appeler : rester bloqué(e) vingt minutes sur un problème est une perte de temps, pas une preuve de courage.

Avec les bons outils :

  • Visual Studio Code pour écrire votre code. L'extension Live Server vous permet de voir votre page se mettre à jour à chaque enregistrement.
  • Un navigateur pour tester votre site, avec son inspecteur pour comprendre ce qui se passe quand quelque chose ne s'affiche pas comme prévu. Pour tester la version mobile, ouvrez le mode responsive et choisissez un appareil précis dans la liste, pas le mode « Adaptatif », qui affiche parfois des bugs qui n'existent pas.
  • MDN, la documentation de référence du web, pour vérifier comment fonctionne une balise ou une propriété.

En sauvegardant votre travail à chaque partie.

Votre projet vit dans un dossier de travail. À la fin de chaque partie, copiez ce dossier dans vos documents sur le serveur de l'IUT et renommez la copie partie-1, partie-2, etc. Ne modifiez jamais ces copies : elles gardent la trace de votre progression et servent de sauvegarde.

SAE105/
└── blue_prince/
    ├── dossier_de_travail/    ← le dossier dans lequel vous travaillez
    ├── partie-1/              ← copie de fin de partie 1
    ├── partie-2/              ← copie de fin de partie 2
    └── …

En déposant votre travail sur Moodle.

À la fin de chaque partie, compressez aussi votre dossier de travail en archive .zip et déposez-la sur Moodle, dans l'espace de dépôt de la partie. Ces dépôts permettent à l'enseignant de suivre l'avancement de chacun.

L'enseignant ne vous aidera sur une partie que si la précédente a été déposée sur Moodle. Pensez-y avant de l'appeler !

Comment vous serez évalué(e)

Votre site n'est pas noté en tant que tel. Ce qui est évalué, c'est ce que vous savez faire à l'issue de la SAE.

À la fin du projet, vous passerez une épreuve sur machine, sans accès à internet ni à votre travail. Vous recevrez un petit site construit avec les mêmes techniques que celui du projet. Vous devrez y corriger des bugs, y ajouter des fonctionnalités et répondre à quelques questions sur le code.

Concrètement : si vous avez construit votre site vous-même, l'épreuve vous paraîtra familière. Vous y retrouverez des problèmes que vous avez déjà rencontrés et résolus.

Copier, utiliser l'IA

Tout le monde réalise le même site : il est donc facile de récupérer le code d'un camarade ou de le faire générer par une IA. Personne ne vous en empêchera pendant les séances.

Mais ce code ne vous servira à rien le jour de l'épreuve : sans internet et sans votre site sous les yeux, il ne reste que ce que vous avez compris. Un code récupéré tout fait, c'est un code que vous n'avez pas appris à écrire, et des erreurs que vous n'avez jamais appris à corriger.

En revanche, s'entraider est encouragé : expliquer à un voisin pourquoi sa grille ne s'affiche pas est une excellente façon d'apprendre. La règle est simple : on explique, on ne donne pas son code.
