Étape 0 L'échauffement 15 min, sans internet ni IA

Sur votre propre code :

  1. Déplacez le point de rupture mobile de 767 px à 600 px. Vérifiez à quelle largeur la galerie passe maintenant à une colonne, puis remettez 767 px.
  2. En lisant votre code et sans regarder le site dans le navigateur, tentez de vous rappeler ce qui change sur la page quand la largeur de l'écran passe sous 1024 px.
Indications
  1. Modifiez la condition de votre media query mobile : @media (max-width: 600px). La galerie ne passe plus à une colonne qu'en dessous de 600 px ; entre 601 et 767 px, ce sont les règles de la tablette qui s'appliquent, donc elle reste sur 2 colonnes. N'oubliez pas de remettre 767 px.
  2. Relisez le contenu de votre media query @media (max-width: 1023px) : chaque règle qu'elle contient correspond à un changement. Vous devriez retrouver le bouton burger qui apparaît et le menu qui disparaît, le texte de l'accueil au-dessus du visuel, l'encart « Le saviez-vous ? » sous le contenu principal, la galerie sur 2 colonnes avec le bloc vedette sur une seule rangée, et la fiche technique sous les actualités. Comparez ensuite avec le site dans le navigateur.

Rappel Le principe de toutes les interactions de cette partie

Toutes les interactions de cette partie suivent les mêmes trois étapes :

  1. Sélectionner l'élément qui réagit au clic et celui qui doit changer (querySelector) ;
  2. Écouter le clic (addEventListener) ;
  3. Agir en ajoutant ou en retirant une classe (classList).
// 1. Sélectionner
const bouton = document.querySelector("#mon-bouton");
const boite = document.querySelector("#ma-boite");

// 2. Écouter
bouton.addEventListener("click", function () {
    // 3. Agir
    boite.classList.toggle("visible");
});

JavaScript ne s'occupe pas de l'apparence. Il se contente d'ajouter ou de retirer une classe. C'est le CSS qui décide à quoi ressemble l'élément avec ou sans cette classe. Vous l'avez déjà vu à la partie 4 avec le menu : en ajoutant la classe ouvert à la main, le menu s'affichait. Aujourd'hui, c'est JavaScript qui va l'ajouter à votre place.

Méthode Effet
classList.add("x") Ajoute la classe x
classList.remove("x") Retire la classe x
classList.toggle("x") Ajoute la classe si elle est absente, la retire si elle est présente

Quand ça ne marche pas : la console

Ouvrez l'inspecteur dans le navigateur et l'onglet Console. Si votre script contient une erreur, elle s'y affiche en rouge, avec le numéro de la ligne. L'erreur la plus fréquente :

Uncaught TypeError: bouton is null

Elle signifie que querySelector n'a rien trouvé. Vérifiez trois choses :

  • le sélecteur est-il bien écrit (# pour un id, . pour une classe) ?
  • l'élément existe-t-il dans votre HTML, avec exactement le même nom ?
  • votre balise script a-t-elle l'attribut defer ? Sans lui, le script s'exécute avant que le navigateur ait lu tout le HTML : les éléments n'existent pas encore.
<script src="js/script.js" defer></script>

Pour savoir si un morceau de code s'exécute, ajoutez-y temporairement console.log("clic !"); et regardez si le message apparaît dans la console. Pensez bien à retirer cette commande par la suite !

Plusieurs éléments à la fois : querySelectorAll et forEach

querySelector renvoie le premier élément trouvé. Pour récupérer tous les éléments qui correspondent à un sélecteur, on utilise querySelectorAll : il renvoie une liste d'éléments, même s'il n'en trouve qu'un seul.

// Une liste qui contient toutes les cartes des pièces
const cartes = document.querySelectorAll(".carte");

Attention : une liste n'est pas un élément. On ne peut pas lui appliquer directement classList ou addEventListener : cartes.addEventListener(…) provoque une erreur dans la console. Il faut agir sur chaque élément de la liste, un par un.

Plutôt que d'écrire une ligne par élément, on demande à la liste de se parcourir elle-même avec forEach (« pour chaque ») : la fonction placée entre parenthèses est exécutée une fois pour chaque élément, et son paramètre (ici carte) désigne à chaque fois l'élément en cours.

// Pour chaque carte de la liste, on ajoute la classe "visible"
cartes.forEach(function (carte) {
    carte.classList.add("visible");
});

C'est exactement ce que ferait une boucle for, en plus court et sans compteur à gérer :

// La même chose avec une boucle for
for (let i = 0; i < cartes.length; i++) {
    cartes[i].classList.add("visible");
}

Pour mettre un écouteur sur chaque élément, il suffit de placer le addEventListener à l'intérieur du forEach. C'est ce que vous ferez aux étapes 3 et 4.

Étape 1 Préparer les états dans le CSS 25 min

Avant d'écrire la moindre ligne de JavaScript, préparez dans le CSS l'apparence avec et sans la classe, comme nous l'avons fait lors de la partie précédente pour le menu :

Élément Par défaut Avec la classe
Le texte secret Masqué .visible : affiché
Les réponses de la FAQ Masquées .ouvert sur l'article de la question : réponse affichée, et une bordure colorée sur le côté gauche de l'article

Pour la FAQ, la classe est ajoutée au parent (l'article), mais c'est l'enfant (la réponse) qui doit apparaître. Le sélecteur s'écrit donc :

.faq-item.ouvert .faq-reponse {
    display: block;
}

Lisez-le de droite à gauche : « la réponse qui se trouve dans un article de la FAQ qui a la classe ouvert ».

Testez vos états comme à la partie 4, en ajoutant les classes à la main dans le HTML, puis retirez-les.

Étape 3 Le menu burger 50 min

  1. Un clic sur le bouton burger ouvre le menu. Un second clic le referme.
  2. Problème : sur mobile, quand on clique sur un lien du menu, la page descend jusqu'à la section… mais le menu reste ouvert et cache le contenu. Corrigez ce problème : un clic sur n'importe quel lien du menu doit refermer le menu.

Indice : récupérez tous les liens du menu avec querySelectorAll, puis parcourez la liste avec forEach pour mettre un écouteur sur chaque lien (voir le rappel).

const liens = document.querySelectorAll("#menu a");

liens.forEach(function (lien) {
    lien.addEventListener("click", function () {
        // que doit-il se passer ici ?
    });
});

Faut-il utiliser toggle ou une autre méthode ici ? Réfléchissez à ce qui se passerait avec toggle si le menu était déjà fermé.

Étape 4 La FAQ 50 min

Un clic sur une question affiche sa réponse. Un second clic la masque. Chaque question fonctionne indépendamment des autres.

Vous avez tous les éléments : c'est le même principe que les liens du menu, appliqué cette fois aux articles de la FAQ.

Étape 5 Les défis bonus s'il vous reste du temps

Défi 1 : une seule réponse à la fois

Quand on ouvre une question de la FAQ, toutes les autres se referment. Indice : avant d'ouvrir la question cliquée, parcourez toutes les questions pour leur retirer la classe. Attention, cliquer sur une question déjà ouverte doit toujours la refermer.

Défi 2 : un bouton qui change de texte

Le bouton affiche « Révéler un secret » quand le secret est masqué, et « Masquer le secret » quand il est visible. Vous aurez besoin de deux nouveautés :

  • element.classList.contains("x") renvoie true si l'élément a la classe x, sinon false ;
  • element.textContent = "…" remplace le texte d'un élément.

Défi 3 : un burger qui se transforme

Quand le menu est ouvert, le bouton affiche ✕ au lieu de ☰. Même principe que le défi 2.
